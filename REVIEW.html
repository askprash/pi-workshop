pi-workshop · pre-release review & plan

A safe-beta extension that runs recursive expert workshops with audit artifacts — this doc maps how it works and what to clean up before going public.
Path: ~/.pi/agent/extensions/workshop LoC: 3,267 (single file) Tests: regex-only Status: safe-beta · not public-ready

TL;DR

A functional, security-conscious extension that needs structural cleanup, real tests, and packaging hygiene before it can ship.

  • Architecture is sound — clean privilege split between the assistant-callable workshop tool and the privileged /workshop slash command, scratch nonce policy, planner-output sanitization, manifest with sha256 artifacts.
  • Structural debt — everything lives in one 3,267-line index.ts. Hard to navigate, hard to review, hard to extend. Needs a 6-module split.
  • Tests are theatre — tests/static-tests.mjs only greps the source string. Zero behavioral coverage of parsing, planner sanitization, nonce lifecycle, manifest writes, or cancellation.
  • Three medium security items — manifest write isn't atomic (race), nonce expiry uses wall-clock (clock-skew exploitable), planner JSON silently drops tools/model instead of rejecting (refactor-fragile).
  • Packaging is incomplete — private: true, no LICENSE, peer deps pinned to "*", default model IDs (gpt-5.5, gpt-5.4-mini) look like placeholders, no CHANGELOG, no CI.
  • Estimated effort to ship: ~3 working days for P0+P1 (blockers + hardening), ~1 more day for polish.

1 · What this extension is

A pi-agent extension that orchestrates a "workshop" — multiple expert personas critique an idea over N rounds, a synthesizer convergence-checks each round, and everything is captured as audit artifacts.

The mental model

You give it an idea. It plans 2–4 expert personas (or you specify them), runs each as a child pi process with read-only tools by default, synthesizes their critiques into a working resolution, and repeats for up to N rounds until CONVERGED: YES. Every artifact (prompts, critiques, synthesis, manifest with sha256 hashes) is written under .pi/workshops/<timestamp-slug>/.

The privilege model (the interesting bit)

Two entry points with intentionally different power:

  • Slash commands (/workshop, /workshop-doctor, …) — the user is in the loop, so privileged modes (--local-bash, --expert-subagents, --prototype) are available.
  • Assistant tool (workshop) — invoked by the LLM, so the schema is narrowed (PublicWorkshopParams) to strip cwd, outputDir, localBash, expertSubagents, prototyping, privileged profiles, and per-expert tools/model.

The workshop_scratch tool — exposed only when --prototype is on — is gated by a per-run nonce policy file with an expert allowlist and TTL, but bash inside it runs as the local user. The README is explicit: artifact-contained, not sandboxed.

3 · Findings

Concrete issues from four parallel reviews — architecture, code quality, security, release readiness. Each item is line-anchored in index.ts.

3.1 · Code quality structural debt

CQ-1Single 3,267-line fileHIGH
Schemas, planner, expert runner, scratch tool, observatory UI, CLI parser, manifest writer all live in index.ts. Hard to review, hard to test, hard to onboard contributors. Proposed split below.
CQ-2Placeholder-looking model IDsHIGH
DEFAULT_STRONG_MODEL = "gpt-5.5" and DEFAULT_JUNIOR_MODEL = "gpt-5.4-mini" at L26–27, mirrored into pi-workshop.config.example.json:34–35. These don't correspond to any released model family. Either real IDs the user must override, or placeholders that need replacing before public release.
CQ-3Legacy --research alias still mutates two fieldsMED
At L2629–2630, L536–539, L2901–2902 the deprecated --research flag sets both webResearch and a separate research field, and the fallback (webResearch || research) is duplicated across the slash parser and the tool's prepareArguments. Pick one: collapse research into webResearch at parse time, or remove the alias.
CQ-4Type leaks — nine any contexts/themesMED
L364, L370, L374, L396, L626, L2233, L2243, L2324, L2327 pass context/theme typed as any. Extract real types from pi-tui/pi-coding-agent. Also (parsed as any)[name] at L2592 and JSON.parse(…) as ScratchPolicy at L1538 bypass type checks before validation.
CQ-5Swallowed errors in child-process & FS pathsMED
Empty catches at L764 (force-kill), L822, L932 (child JSON event parse), L1273; silent .catch(() => return) at L614 (listFilesRecursive); modelExists() at L2685 returns true on exception (fail-open). Each should at minimum log to stderr / observatory.
CQ-6Duplicated literals: tool lists, timeoutsLOW
WEB_RESEARCH_TOOLS.split(",") at L349, L350, L696, L2698, L2730; magic 20-file and 256KB scratch limits at L2795, L2797. Extract named constants.
CQ-7Tests don't test behaviorHIGH
tests/static-tests.mjs asserts that certain strings appear in index.ts. A rename or refactor silently breaks it, and broken logic with the right strings still passes. Missing real coverage: slash flag parsing, planner sanitization, scratch nonce lifecycle, config merge precedence, manifest schema, cancellation propagation.

3.2 · Security 3 med · 5 low

SEC-1Manifest write is non-atomicMED
L1558–1565 writeRunManifest() writes the manifest twice (empty artifacts, then with). A concurrent reader or a crash between writes leaves an inconsistent manifest on disk. Fix: write to .manifest.tmp + atomic rename.
SEC-2Nonce expiry uses wall clockMED
L1527–1529, L2783–2784: TTL computed as Date.now() + ttl, checked via Date.parse(expiresAt). System-clock rollback (or NTP adjustment, or untrusted config-supplied TTL) shifts the validity window. Fix: store an absolute mono-clock baseline or refuse to evaluate if clock skew is detected.
SEC-3Planner JSON silently drops tools/modelMED
L1249–1276, L1691–1710: README claims planner JSON "cannot smuggle tools or model", and today it can't — those fields are ignored rather than rejected. A future refactor that accesses planned.tools reintroduces the hole. Fix: reject planner output containing those fields with a clear error, not silent drop.
SEC-4Scratch policy file isn't symlink-checked on readLOW
L1537–1542 readScratchPolicy() reads .scratch-policy.json directly. A symlink swap could substitute an older policy with a stale nonce/allowlist. Fix: fs.realpath + assert it's still under the workshop dir.
SEC-5Detached children can spawn descendants outside the groupLOW
L762, L797, L916: spawns use detached: true; cancel sends SIGTERM to -pid. A child that re-detaches escapes the group. Fix: track descendants explicitly or avoid detached.
SEC-6Downloads scan leaks filenames into manifestLOW
L695–708, L2009: every non-hidden file landing in ~/Downloads during a run gets logged in the audit manifest. If the manifest is committed/shared, private filenames leak. Fix: opt-in flag, or filter to files written by child processes.
SEC-7/workshop-cancel doesn't await cleanupLOW
L3092–3093: controller.abort() returns immediately. Pending manifest write / scratch-policy cleanup may be interrupted. Fix: await a cleanup promise; write a CANCELLED sentinel synchronously.
SEC-8Mixed expert-name sanitization pathsLOW
L568 (safeSegment), L1258, L1803: three different regexes "sanitize" expert names in different contexts. Today they all defeat traversal, but the inconsistency is a refactor footgun. Fix: route every path-forming use through safeSegment.

3.3 · Release readiness packaging, docs, CI

REL-1Packaging is private-modeHIGH
package.json: "private": true, no license, no repository, no bugs, no homepage, no author, no LICENSE file at repo root. Peer deps are all "*" — npm will accept any version. Decide on scope (@earendil-works/pi-workshop?), pin peer ranges, add license + repo metadata.
REL-2No CI, no lint, no typecheckHIGH
No .github/workflows/, no tsconfig.json, no ESLint/Biome, no Prettier. TypeScript is written but never strict-checked. For a TS package going public, at minimum: tsc --noEmit, lint, formatter, smoke-test in GH Actions on PR.
REL-3README missing install + quick-start + model setupMED
No pi install instructions, no minimal end-to-end example, no clarification of what to do if the default models (gpt-5.5/gpt-5.4-mini) aren't reachable. No troubleshooting / uninstall / CHANGELOG. No screenshots of the observatory.
REL-4No behavioral testsHIGH
Already called out as CQ-7. Re-flagged here because shipping without behavioral tests is the single largest release risk. At minimum: slash-flag parser, config merge, planner sanitization, scratch nonce expiry/symlink, manifest schema, cancellation.
REL-5No platform statement; code is POSIX-onlyMED
process.kill(-pid), ~/Downloads, path separators — works on macOS/Linux, will fail on Windows. README should either explicitly say "macOS/Linux only" or add a Windows compatibility shim.
REL-6Stability / versioning story is informalLOW
"safe-beta" in the version isn't documented. Manifest carries version: 1 but the schema isn't documented. Slash flags aren't declared stable or experimental. Add a short stability statement to README and a manifest schema reference.
REL-7No privacy statementLOW
No telemetry calls detected in the source — good. README should explicitly say so ("no telemetry, no external calls beyond user-configured model APIs and explicit --web-research tools").

5 · Open questions for you

Decisions that block or steer P0. Worth resolving before any of the cleanup work starts.

  1. Models — are gpt-5.5/gpt-5.4-mini real IDs in your provider, or placeholders? If placeholders, what should the default be — or should we ship with no default and force the user to configure?
  2. Publishing target — npm under @earendil-works/? Or distribute via pi install <git-url> only? Affects scope, registry, version policy.
  3. Windows — in-scope or explicitly out-of-scope for the public beta?
  4. Downloads scan — keep on-by-default (current behaviour), or flip to opt-in to avoid privacy surprises?
  5. Legacy --research — deprecate with a warning, or drop entirely?
  6. Manifest schema versioning — if you bump the schema later, is the policy "old runs are read-only / not migrated" or "tool migrates on read"?
  7. Stability promise on slash flags — declare them stable, or mark some as experimental?
